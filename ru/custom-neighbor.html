9. Как заменить соседа своей моделью

Самый простой безопасный способ: оставляем родной AI Соседа, меняем только тело. Разбираем Skeletal Mesh, Skeleton, Retargeting и чиним T-Pose, масштаб и «провал под землю». Основано на NeighborModKit (ModDB) и Hello Neighbor Wiki.

Что мы сделаем + дисклеймер

Создадим дочерний Blueprint от BP_NeighborCharacter (оригинал не трогаем!), назначим свой Skeletal Mesh, проверим Skeleton и Animation Blueprint, поставим на уровень с зонами BP_AreaNeighborHouse и протестируем погоню.

⚠️
Важно: метод не гарантирован для всех сборок

Mod Kit обновлялся (4.18 → 4.19.1 → 4.20.3), имена Blueprint и структура Skeleton могли отличаться. Если у вас нет BP_NeighborCharacter с таким именем — ищите поиском Neighbor* / AI* / Enemy*. Принцип (дочерний класс + тот же Skeleton) одинаков везде, детали — смотрите в своей сборке.

Словарь

ТерминПростыми словами
Skeletal MeshМодель с костями внутри (персонаж), умеет гнуться. Static Mesh — статуя, Skeletal — человек
Skeleton AssetНабор костей (бедро → голень → стопа). Один Skeleton — много моделей с одинаковыми костями
Rig / BonesСами кости + как они гнутся. Художник красит веса (Skin Weights): какая вершина за какой костью тянется
Animation BlueprintЛогика «когда играть ходьбу/бег/поймал». Берёт скорость AI и включает нужную анимацию
Retargeting / Bone MappingПересадка анимаций с одного скелета на другой («эта кость = та кость»). Работает идеально только на одинаковых скелетах

Импорт персонажа

  • Blender: модель в A-Pose/T-Pose, кости по именам UE (root, pelvis, spine, head, upperarm_l/r…), Apply Scale/Rotation, рост ~180 см.
  • Export FBX: Skeletal Mesh + Skeleton, 2014–2018. Ткани/физику (Cloth) не включайте — 4.20 APEX капризный.
  • Import: Skeletal Mesh=true, Import Skeleton (новый или выбрать скелет Соседа! — см. ниже), Import Materials=false, Normal Import Method=Import Normals. Материалы назначьте свои (см. урок 7).

Почему нельзя просто подменить тело

Анимации записаны под конкретный Skeleton (длины костей, имена, иерархия). Чужая модель с другим скелетом = руки из спины. Варианты:

  • Идеально: ваша модель на том же Skeleton, что Сосед (экспорт с его скелетом / Bone Mapping 1-в-1). Все анимации встают сразу.
  • Хорошо: похожий гуманоид → Retarget Manager → Set up Rig (Humanoid) → Retarget Anim Blueprints. Ходьба ок, пальцы/лицо могут кривиться.
  • Плохо: четвероногий/монстр с другим числом костей → нужны свои анимации с нуля. Для первого мода не беритесь.
  • Лайфхак NeighborModKit: готовый Kit с ModDB уже содержит настроенного соседа-заготовку — замените только Mesh, скелет оставьте его.

Замена внешнего вида: 10 шагов

1

Найти Blueprint соседа

Content Browser → поиск NeighborCharacter / BP_Neighbor / Neighbor. Откройте, посмотрите Components: там Skeletal Mesh (тело) + Capsule Collision + AI Controller ссылка + Animation Blueprint. Запомните имена.

2

Не ломаем оригинал!

Оригинал — эталон игры. Правый клик → Create Child Blueprint Class → BP_Neighbor_My. Все правки — только в ребёнке. Сломали? Удалили ребёнка, оригинал цел.

3

Создаём ребёнка

Child наследует весь AI. В нём видно те же компоненты, но с жёлтыми стрелками наследования. Не меняйте Capsule и AI — только Mesh.

4

Меняем Skeletal Mesh Component

Выберите Mesh → Details → Skeletal Mesh → ваша модель. Если список пуст — модель не импортировалась как Skeletal (переимпортируйте с костями).

5

Назначаем свою модель

Подгоните Location/Rotation меша внутри капсулы (обычно Z -90, чтобы ноги на дне капсулы). Scale 1.0! Не тяните мышью — сломаете пропорции с Collision.

6

Проверяем Skeleton

Откройте ваш Mesh → Skeleton Tree. Сравните с оригиналом: совпадают имена root/pelvis/spine? Если ваш Skeleton другой — либо переключите Mesh на скелет Соседа (Details → Skeleton → выбрать соседский + Retarget), либо смиритесь с ручным Retarget.

7

Проверяем Animation Blueprint

В ребёнке Anim Class должен остаться родной соседский. Если поставили None — будет T-Pose. Если ваш скелет другой — продублируйте AnimBP и переназначьте в Retarget Manager.

8

Проверяем материалы

Назначьте свои материалы на слоты (кожа/рубашка/штаны). Розовый = пустой слот. Сохраните (Compile + Save).

9

Ставим на уровень

Перетащите BP_Neighbor_My на карту + добавьте зоны BP_AreaNeighborHouse (дом соседа) и BP_AreaPlayerHouse (дом игрока) из Kit — без них AI не понимает территорию (см. Wiki Update 2). Электрика — через BP_GeneralSwitch.

10

Тестируем AI

Play: пошумите (бег, бросьте предмет), зайдите в дом соседа. Он должен: патрулировать → заметить → погнаться → поймать (кат-сцена/телепорт). Если ходит, но T-Pose — см. диагностику.

Если анимации сломались: 6 диагнозов

T-Pose (руки в стороны, скользит)

Причина: нет Anim Blueprint или чужой Skeleton без Retarget.
Фикс: верните родной Anim Class; проверьте Skeleton совпадает; Reimport с правильными костями.

Руки/ноги вывернуты

Причина: Bone Mapping перепутан (левая кость → правая) или разная длина костей.
Фикс: Retarget Manager → Humanoid Rig → проверьте каждую кость; Scale модели 1.0.

Модель гигантская / крошечная

Причина: Blender Unit не см.
Фикс: переэкспорт Scale 1.0. Не компенсируйте Scale в Blueprint — сломаете Capsule/AI.

Под землёй / по пояс в полу

Причина: Mesh смещён внутри Capsule.
Фикс: Mesh Location Z ≈ -половина высоты капсулы (обычно -90). Player Start тут ни при чём — двигаем меш, не капсулу.

AI ходит, но модель не двигается (скользит)

Причина: AnimBP не получает скорость (чужой Character без нужных переменных).
Фикс: используйте дочерний класс от родного Соседа, а не чистый Character. Тогда скорость течёт сама.

Анимации не подходят стилистически

Причина: монстр ходит как бухгалтер.
Фикс: честно: нужны свои анимации или смириться. Для хоррора T-Pose-монстр иногда даже страшнее — обыграйте светом (см. ночь).

Проверка + советы

  • Оригинал не тронут, всё в BP_Neighbor_My.
  • Скелет совпадает, AnimBP родной, материалы не розовые.
  • На уровне есть обе Area-зоны, сосед патрулирует и ловит.
  • Упакованный .pak тестили, а не только PIE.
