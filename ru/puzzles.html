3. Головоломки: двери, ключи, ключ-карты, доски и лом

Ядро Hello Neighbor: дверь на Timeline, замок с Boolean-переменными, 3 цветных ключа, электронный считыватель с лампой, заколоченный проход и лом. В финале соберём цепочку из 6 этапов как в оригинале.

Что мы сделаем

Создадим Blueprint BP_Door (открывается по E рядом), BP_Key (подбирается), замок с проверкой, электронную дверь с картой, заколоченную дверь с 3 досками и лом. Свяжем всё в квест: ключ → шкаф → лом → доски → ключ-карта → электронная дверь.

Trigger (Box Collision / Trigger Volume) — невидимая зона, которая сообщает «игрок вошёл/вышел». Timeline — нода-анимация по времени (0→1 за N сек). Boolean — переменная да/нет (true/false). Взаимодействие (Interaction) — в Mod Kit обычно клавиша E через Action Mapping + Overlap или Line Trace.

Простая дверь: закрыта → открывается с анимацией

Что понадобится

  • Static Mesh двери (SM_Door) + рама. Pivot двери — на петле (сбоку), иначе дверь крутится вокруг центра как пропеллер!
  • Box Collision 200×200×200 перед дверью как Trigger.
  • Blueprint Class → Actor → BP_DoorSimple.
1

Собираем компоненты

Откройте BP_DoorSimple → вкладка Viewport: добавьте Static Mesh (рама, Static, BlockAll) как Root, Static Mesh (полотно, Movable!), Box Collision (Trigger). Полотно — именно Movable, иначе Timeline не сдвинет. В Collision пресете триггера: OverlapAllDynamic, Generate Overlap Events = true.

2

Pivot на петлю — критично

Выберите полотно → Details → проверьте Pivot. Если крутится странно: либо в Blender сдвиньте origin к краю, либо в Blueprint вложите полотно в Scene Component (DoorPivot) на краю и вращайте Pivot, а не меш. Это приём №1 от T-Pose-дверей из ModDB-туто «Door, Boards, Nails, Lock and Key».

3

Timeline 0→90° за 1 сек

Event Graph → правый клик → Add Timeline, имя TL_Open. Откройте: Add Float Track → OpenAngle, точки (0с=0, 1с=90), галочка Use Last Keyframe. Длина 1.0. Теперь дверь плавно, а не телепортом.

Как работает Blueprint

OnComponentBeginOverlap (Box)
игрок вошёл в зону
↓
Cast To BP_PlayerCharacter + IsValid
проверяем, что это игрок, а не стул
↓
Set PlayerNear = true + показать «Нажмите E»
через Widget, см. урок 6
↓
InputAction Interact (E) + Branch [PlayerNear?]
нажали E рядом?
↓
FlipFlop → A: Play TL_Open, B: Reverse TL_Open
открыть / закрыть
↓
Update: TL_Open → Lerp 0→90 → SetRelativeRotation (DoorPivot)
каждый кадр поворачиваем
OnComponentBeginOverlap / EndOverlap — события триггера. Begin — «вошёл», End — «вышел» (там ставим PlayerNear=false). В 4.20 у Box Collision это именно Component-события, не Level-события.
Cast To + IsValid — фильтр «только игрок». Без Cast дверь откроет и сосед, и брошенный стул. IsValid спасает от Accessed None, если игрок уже удалён.
FlipFlop — переключатель: первое нажатие E идёт в A (открыть), второе — в B (закрыть). Не используйте два отдельных E — запутаетесь.
SetRelativeRotation — крутим относительно рамы, а не мира. Поэтому дверь работает, даже если весь дом повёрнут на 90°.
⛔
Частая ошибка: дверь открывается сквозь стену / через стену

Триггер слишком большой (радиус 500) — E срабатывает из соседней комнаты. Уменьшите Box до 180×180 и поставьте его только с нужной стороны. Второй вариант — проверка взгляда через Line Trace (см. продвинутые).

Дверь с ключом: полная схема

Boolean — тип «да/нет»: HasKey (у игрока есть ключ?), IsLocked (замок закрыт?), DoorOpen (открыта сейчас?). Храните HasKey в PlayerCharacter или GameMode/Inventory, а IsLocked/DoorOpen — в самой двери.

1

Ключ BP_Key: подбор

Static Mesh ключа (маленький, 20 см) + Sphere Collision (Overlap). Граф: OnComponentBeginOverlap → Cast To Player → Player.HasKey = true → Play Sound (Pickup) → Destroy Actor (ключ). Добавьте Do Once перед Destroy, чтобы двойной Overlap не дал 2 ключа. Точку спавна ключа — в шкаф из дома.

2

Дверь проверяет ключ

В BP_DoorKey добавьте Bool IsLocked = true. На E: Branch [IsLocked?] → true: Cast к Player → Get HasKey → Branch → true: Set IsLocked=false + Play Unlock + Play TL_Open; false: Print «Нужен ключ!». Если IsLocked уже false — сразу TL_Open.

InputAction Interact (E) возле двери
↓
Branch: IsLocked?
если false — сразу открыть
↓ да, закрыта
Get Player → Get HasKey
↓
Branch: HasKey?
↓ true / false
TRUE: Set IsLocked=false → Unlock-звук → Play TL_Open | FALSE: Print «Нужен ключ»
Get HasKey — читаем чужую переменную через Cast: Cast To BP_Player → As BP_Player → Get HasKey. Пин As — это «тот самый игрок». Без Cast пин будет пустым (Accessed None).
Set IsLocked=false (Unlock) — меняем состояние замка один раз. После — дверь как обычная (FlipFlop).
Почему HasKey в игроке, а IsLocked в двери? Ключ — свойство игрока («я несу»), замок — свойство двери («я закрыта»). Если наоборот — второй ключ сломает первую дверь.

Практика: сделайте BP_Key (KeyID int, Editable): 3 копии с ID 1/2/3 и цветами (красный/синий/зелёный материал). В игроке — Array int Keys или 3 Bool (HasRed/HasBlue/HasGreen). Дверь: NeededID → Contains в массиве. Так ключ не тратится зря на чужую дверь.

💡
Совет: тратится ли ключ?

Для Hello Neighbor-стиля ключ обычно не исчезает после открытия (им ещё подвал открывать). Если хотите «одноразовый» — после Unlock делайте Remove from Array. Решите заранее, иначе игрок выбросит ключ и застрянет.

Ключ-карта и электронная дверь

1

Считыватель: коробка + лампа

Рядом с дверью: SM_Reader (коробка 15×25×8) + Point Light маленькая красная + Static Mesh лампочки (Emissive красный материал). Всё в одном BP_CardDoor. Переменная HasCard (bool) в игроке, Powered (bool) в двери.

2

Логика считывателя

E у ридера: HasCard? → true: Set Powered=true → Set Light Color зелёный + Set Material лампы на зелёный Emissive → Play Sound (Beep/Open) → Play TL_Open; false: мигнуть красным (Timeline 0.2с) + Print «Нужна ключ-карта». Лампа — два материала в массиве + Set Material (Element 0).

E на Reader → Get HasCard
↓
Branch HasCard → FALSE: красный blink + звук ошибки
↓ TRUE
Set Powered=true → SetLightColor зелёный → SetMaterial лампы → PlaySound Beep
↓
Play TL_Open (та же дверь)
🔊
Важно: звук

Звук — Play Sound at Location (нужен Sound Cue из Kit). Громкость 1.0, Location — позиция ридера. Без звука игрок не поймёт, сработало или нет. Держите 2 Cue: success и denied.

Доски на двери: заколоченный проход

Проход, который нельзя открыть ключом — только ломом. Состав: BP_BoardedDoor: рама + 3 Static Mesh доски (каждая Movable, BlockAll) + 2 Box Collision (одна блокирует проход, вторая — триггер для лома). Переменная BoardsLeft = 3.

  • Каждая доска — отдельный меш со своим Pivot в центре (её будем «отрывать» со звуком и физикой).
  • Пока BoardsLeft > 0 — основная дверь заблокирована (Branch не пускает TL_Open).
  • Доски чуть повёрнуты (Rotation Z ±10°) — так атмосфернее, как в оригинале.

Лом: берём → бьём → доска отлетает

1

Подбор лома

BP_Crowbar: Mesh + Sphere Overlap. На Overlap: Player.HasCrowbar = true → Attach лом к руке (AttachToComponent HandSocket) → Destroy оригинал или Hide. Проверка «держит ли лом» — Bool HasCrowbar в игроке. Без него E на доске даёт «Нужен лом!».

2

Какая доска? Трассировка или триггер

Простой вариант: у каждой доски свой Sphere Trigger + в доске Bool IsTargeted. Сложный (лучше): Line Trace от камеры на 250 см → Hit Actor → Cast To BP_Board → снять именно её. Для первого мода хватит триггеров: подошёл к доске с ломом → E → снимается ближайшая.

3

Снятие доски со звуком и анимацией

На E: HasCrowbar? → true: BoardsLeft-- → Play Sound (Wood Crack) → Detach + Simulate Physics на 1с (доска падает) + Delay 1.0 → Destroy Actor → если BoardsLeft==0: разблокировать дверь (IsLocked=false). Анимация — просто Add Impulse + Spin (SetRelativeRotation по Timeline 0.3с),этого хватает для вау-эффекта.

E возле доски → Get HasCrowbar
↓
Branch → FALSE: «Найдите лом!»
↓ TRUE
BoardsLeft-- → Crack-звук → Simulate Physics + Impulse
↓
Delay 1.0 → Destroy Board → если 0: Unlock дверь

Своя головоломка из 6 этапов (как в Hello Neighbor)

Финальный квест уровня:

  1. Красный ключ на кухне → открывает шкаф в спальне (дверь с NeededID=1).
  2. В шкафу — лом (HasCrowbar=true).
  3. Ломом снимаем 3 доски с двери в подвал (BoardsLeft 3→0).
  4. За досками — ключ-карта на полке (HasCard=true).
  5. Картой открываем электронную дверь (лампа красная→зелёная).
  6. За ней — финал: рычаг/вентиль (см. слив воды) или записка «Вы выбрались!».

Свяжите этапы через GameMode или Level Blueprint: Bool Stage1_Key, Stage2_Crowbar… + Widget-подсказки (см. текст на экране). Тестируйте по одному этапу: закройте остальные двери заглушками, иначе не поймёте, где сломалось.

💡
Совет: как улучшить

Добавьте таймер (дверь закрывается через 5с), звук скрипа Timeline, «ложный» синий ключ (открывает кладовку с батарейкой), доски разного размера (2 E вместо 1). Но сначала — чтобы работала база из 6 этапов без ошибок.

Проверка + ошибки

  • Дверь открывается только рядом и только по E, через стену — нет.
  • Без ключа — «Нужен ключ», с ключом — Unlock + анимация.
  • Красный ключ не открывает синюю дверь (и наоборот).
  • Карта зажигает зелёную лампу + звук, без карты — красный blink.
  • Лом снимает все 3 доски по очереди, проход открывается.
Дверь вращается вокруг центра, а не петли

Pivot в центре меша. Создайте Scene→DoorPivot на краю проёма, вложите полотно, вращайте Pivot. Или сдвиньте Pivot в Blender (origin to edge).

Trigger срабатывает через стену

Уменьшите Box, перенесите его только перед дверью, добавьте проверку дистанции (Vector Length < 200) или Line Trace.

Ключ подобрал, а дверь всё равно «Нужен ключ»

HasKey стоит не в том игроке (в меню-персонаже, а не в игровом) или Cast идёт не к тому классу. Проверьте через Print String значение HasKey сразу после подбора.

Timeline дёргается / дверь телепортируется

Длина Timeline 0 или нет Lerp. Поставьте 1.0с, 2 ключа, Update → Lerp → SetRelativeRotation. Полотно — Movable, не Static!

Звука нет

Нет Sound Cue или громкость 0. Проверьте Play Sound at Location с тестовым Cue из Kit. Наушники/микшер — банально, но бывает.
