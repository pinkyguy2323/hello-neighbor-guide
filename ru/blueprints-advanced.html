8. Продвинутые Blueprint

Учим Blueprint общаться: ссылки, Cast, Interface, Dispatcher. Делаем Functions, массивы дверей, структуры ключей, Enum состояний и большую систему «генератор → рубильник → лампы → электрозамок». Плюс честно про сохранения.

Что мы сделаем

Систему из 4 акторов: BP_Generator (бензин + кнопка) → BP_Switch (рубильник) → 3× BP_Lamp (свет) + BP_ElectroDoor (замок). Пока генератор выкл — лампы не горят, дверь не открывается даже с ключом. Включили — свет, звук, дверь с питанием.

4 способа связи Blueprint: когда какой

СпособКакКогдаПример
Direct ReferenceПеременная Object → выбрать актор пипеткой на уровне (Editable, Eye)2–3 объекта, связь навсегда (дверь знает свой ключ)Дверь.TargetLamp — конкретная лампа
CastCast To классу → Get переменная«Ты игрок? Дай HasKey». Жёсткая связь, но простаяДверь → Player → HasKey
Blueprint InterfaceОбщий «договор»: BPI_Interactable с функцией Interact. Кто угодно реализуетМного разных объектов с одной кнопкой E (дверь, вентиль, ТВ, рубильник)E → Line Trace → Interface Interact — один код для всего!
Event Dispatcher«Радио»: генератор кричит PowerOn, кто подписан — слышитОдин → многим (генератор → 10 ламп + дверь + ТВ)Dispatcher OnPowerChanged(bool) — лампы подписаны

Правило выбора: 1 дверь + 1 ключ = Direct. Проверка «игрок ли?» = Cast. Кнопка E для всего = Interface. Генератор для всего дома = Dispatcher. Не тащите Cast через всю карту — получите «спагетти» и циклические зависимости.

💡
Совет: Interface за 3 шага

1) Content → Add New → Blueprints → Blueprint Interface → BPI_Interact (функция Interact с Input Player). 2) В каждом интерактиве Class Settings → Add Interface. 3) На E: Trace → Does Implement Interface? → Interface Message Interact. Больше никаких Cast к 10 классам!

Functions и Custom Event

  • Function: свой «рецепт» с Inputs/Outputs/Return. Пример TryOpenDoor(Player) → Returns Success(bool): внутри проверка ключа + Timeline. Локальные переменные живут только внутри функции (временные счётчики).
  • Custom Event: своя «кнопка» без возврата: PowerOn / PowerOff / Alarm. Вызывается из других Blueprint (Call). С Replicates — для мультиплеера (в Mod Kit почти не нужен).
  • Когда что: нужно вернуть да/нет или число → Function. Нужно просто «сделай!» → Custom Event / Dispatcher.
  • Чистота: вынесите в Function всё, что повторяется 2+ раза (проверка ключа, мигание лампы). Имя — глагол: UnlockDoor, DrainWater, SetLampColor.

Arrays, Struct, Enum на примерах дверей

Array — список

Переменная → тип → иконка сетки (Array). Lamps (Array BP_Lamp): Add 3 лампы пипеткой. ForEachLoop → Set IsPowered — одна нода зажигает все! Полезно: Length, Add, Remove, Contains, Get(index). Пример: массив дверей подъезда — закрыть все сиреной одним циклом.

Struct — карточка объекта

Add New → Blueprints → Structure → S_Key: KeyID (int), KeyName (text), KeyColor (linear color), Used (bool). Теперь ключ — одна переменная-структура вместо 4, а массив Inventory (Array S_Key) — весь рюкзак! Split Struct Pin — развернуть поля, Make Struct — собрать.

Enum — состояние

Add New → Blueprints → Enumeration → E_DoorState: Locked, Closed, Opening, Open, Closing. В двери переменная State. Переходы: Locked→(ключ)→Closed→(E)→Opening→(Timeline Finished)→Open. Проверка — Equal (Enum) + Switch on Enum. Больше никаких «IsLocked + DoorOpen + IsAnimating» трёх Bool, что противоречат друг другу!

E → Switch on E_DoorState
↓
Locked: проверить ключ | Closed: Opening+Play TL | Open: Closing+Reverse | Opening/Closing: игнор

Сохранения: честно про Mod Kit

В чистом UE 4.20 есть SaveGame + Save/Load Game to Slot — можно сохранить HasKey, WaterDrained, позиции. Но: в Hello Neighbor Mod Kit упаковка и GameMode кастомизированы под моды/Workshop, оригинальный Сосед хранит AI-память по-своему, а слоты могут не переживать обновление мода. Поэтому: простые флаги (ключи, слив) — сохраняйте смело через SaveGame; полную «память соседа» — не обещайте, тестируйте на упакованном .pak, а не только в PIE. Если Save не завёлся — скажите игрокам честно «уровень проходится за раз», это нормально для мода.

Практика: электричество дома

1

Генератор BP_Generator

Mesh + Trigger + звук тарахтения (Loop). Переменные HasFuel (bool), IsRunning (bool), Dispatcher OnPowerChanged (bool Powered). На E: HasFuel? → true: IsRunning=true → Play звук → Call OnPowerChanged(true) → Widget «Генератор запущен»; false: «Нужен бензин! (канистра в сарае)». Канистра — BP_Pickup, ставит HasFuel=true.

2

Рубильник BP_Switch

Подписан на OnPowerChanged. Свой Bool SwitchOn (рычаг). Итоговое питание: Powered = GeneratorRunning && SwitchOn && HasFuel. На E дёргаем SwitchOn → пересчёт → снова Call лампам/двери. Так дверь не откроется при заведённом генераторе, но выключенном рубильнике — как в реальности!

3

Лампы и дверь

BP_Lamp: на OnPowerChanged → Branch Powered → Set Light Visible + Set Emissive 1.0 / 0.0 + звук щелчка. BP_ElectroDoor: та же подписка + своя проверка: E → Branch Powered? → false: «Нет электричества!» (даже с ключом!) → true: дальше обычная проверка ключа из урока 3. В Mod Kit есть родной BP_GeneralSwitch — если делаете дом Соседа, привяжитесь к нему (Сосед сам его находит!).

E на генераторе → HasFuel? → Call OnPowerChanged(true)
↓ подписаны
Switch: Running && SwitchOn → Lamp: свет вкл → Door: Powered=true
↓
E на двери: Powered && HasKey → открыть
⚡
Важно: архитектура, а не спагетти

Лампы не должны Cast к генератору каждая. Генератор кричит в Dispatcher, лампы слушают. Добавить 10-ю лампу = подписать, а не переписывать генератор. Это и есть «архитектура системы».

Проверка + ошибки

  • Без бензина — «Нужен бензин», с бензином — тарахтит, лампы горят.
  • Рубильник выкл — лампы гаснут, дверь «Нет электричества».
  • Interface E работает и на двери, и на вентиле, и на ТВ без Cast.
  • Enum двери не даёт открыть Opening повторно.
Dispatcher никого не будит

Забыли Bind Event на BeginPlay ламп/двери. Bind — один раз при старте, Call — при смене питания. Проверьте синий пин Target привязан.

Циклическая зависимость (Cyclic)

Дверь Cast к лампе, лампа Cast к двери. Разорвите через Interface/Dispatcher — они не требуют жёстких ссылок.
